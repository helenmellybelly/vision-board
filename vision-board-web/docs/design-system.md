# 꿈의 정원 일지 — 디자인 시스템 (v6.15)

서비스 전체의 시각 언어 단일 소스. 코드의 단일 소스는 `app/globals.css`(@theme 토큰)와 `lib/colors.ts`(섹션 팔레트)이며, 이 문서는 그 사용 규칙을 설명한다.

## 1. 폰트

| 역할 | 폰트 | 사용처 |
|---|---|---|
| **UI 전체** | Pretendard Variable | 모든 UI 텍스트 — 헤드라인·본문·버튼·말풍선. 위계는 굵기·크기·자간으로만 표현 |
| **아트** | tvN Enjoystories (`.font-script`) | 콜라주 보드 타이틀·연도, 문구 스티커(script), 배경화면 — **`components/collage/**` 전용** |

규칙 (v6.15, 기계 검증됨): UI에는 Pretendard 하나만 쓴다 — 통일감이 최우선.
`.font-script`(손글씨)는 비전보드 "작품" 영역(콜라주·스티커·배경화면)에서만 허용된다.
구 `.font-display`(Gowun Batang)는 제거됨 — 어디서도 쓰지 않는다.
가드: `node scripts/check-typography.js` (verify 스크립트에 포함) — font-display 사용과 콜라주 밖 font-script 사용을 잡는다.

폰트 파일: `public/fonts/Enjoystories.woff` 셀프호스팅. canvas `ctx.font`와 family명을 공유해야 해서
next/font(해시 family) 대신 `globals.css`의 평문 `@font-face`를 쓴다. 라이선스: 무료·상업적 사용 가능.

## 2. 타입 스케일 (7단계)

`globals.css`의 `@theme`에 정의 — `text-[15px]` 같은 임의값과 `text-sm` 같은 기본 유틸리티 사용 금지.

| 토큰 | 크기 / 행간 | 용도 |
|---|---|---|
| `text-display-lg` | 32px / 1.3 | 히어로 헤드라인 |
| `text-display` | 24px / 1.35 | Act·페이지 대표 타이틀 |
| `text-title` | 20px / 1.4 | 페이지 제목, 섹션 타이틀 |
| `text-heading` | 17px / 1.5 | 섹션 헤더, CTA 버튼 |
| `text-body` | 15px / 1.65 | 본문, 말풍선 |
| `text-caption` | 13px / 1.5 | 보조 설명, 모드 탭 |
| `text-micro` | 11px / 1.4 | 힌트, 라벨, 캡션 |

예외: 콜라주 보드의 연도·스티커는 보드 폭 기반 `cqi` 단위(아트 타이포그래피)로 스케일 밖 허용.

## 3. 간격 스케일

Tailwind 4px 그리드 위에서 의도를 갖고 쓴다 — 같은 화면에서 임의로 섞지 않는다.

| 간격 | 클래스 | 용도 |
|---|---|---|
| 4~6px | `gap-1`~`gap-1.5`, `space-y-1.5` | 한 덩어리 안의 밀착 요소 (카드 내부, 도트, 사진 그리드 셀) |
| 8~10px | `mt-2`, `mb-2.5`, `gap-2` | 제목↔부속 텍스트, 헤더↔콘텐츠 — 같은 블록의 연결 |
| 12px | `gap-3`, `space-y-3` | 형제 카드·섹션 항목 사이 |
| 16px | `mt-4`, `mb-4` | **새 주제 블록**의 시작, 콘텐츠↔CTA |
| 24px+ | `mt-6`+ | 페이지 단위 구획 |

원칙: 결론 문구는 그 근거(이미지·카드)에 *바짝*, 새 주제는 *넉넉히*. flex-1로 잉여 공간을
중간 요소가 흡수하게 두지 말 것 — 잉여는 `justify-center`로 가장자리에 보낸다 (v6.15 온보딩 교훈).

## 5. 버튼 상태 규칙

CTA 라벨은 사용자의 실제 상태를 반영한다 — 콘텐츠가 없는데 "수정"을 권하지 않는다.

| 상태 | 라벨 |
|---|---|
| 해당 단계 콘텐츠 없음 | **작성하기 →** (강조 굵기) |
| 콘텐츠 있음 | 수정하러 가기 → |

판별 기준은 표시 중인 콘텐츠 그 자체(슬롯 답변·sceneText·miniStory) — 사진 업로드 여부와 무관.

## 7. 포커스 & 인터랙션

- 전역 `:focus-visible`: 2px `#1C1B19` 아웃라인. 단 **텍스트 입력(input/textarea)은 예외** — 보더 색 전환(`focus:border-[#1C1B19]`)이 포커스 표시를 대신한다 (보더+아웃라인 이중선 방지).

## 8. 콜라주 보드 & 배경화면 (v9.0 그리드 재설계)

**모듈 분담** — 수치는 `lib/collageTokens.ts`(순수, 무의존), 배치 대수는 `lib/collageGrid.ts`,
"어떤 그리드를 고를까"는 `lib/collageTemplates.ts`, 렌더는 `CollageBoard`(DOM)·`lib/wallpaper.ts`(canvas).
v8.7까지 `titleBottom` 공식이 5곳에 중복돼 있었는데, 토큰 모듈이 그 단일 소스가 됐다.

### 배치의 진실 원천은 좌표가 아니라 그리드

`CollageLayout.grid`(`GridSpec`)가 진실이고 `items` 좌표는 `materialize()`가 파생시킨다.
v8.2~v8.7은 좌표에서 그리드를 역산(`inferGridSpans`)했는데, 역산이 실패하면 자동 정렬이 통째로 죽어
"한 번 자유롭게 옮겼더니 그 뒤로 정렬이 영영 안 됨"이 됐다. 이제 **빈틈 0이 측정이 아니라 정리**다:
row 밴드는 `sum(spans) === cols`, hero 밴드는 `1 + 2×(cols−2)`개가 정확히 `cols`를 점유한다.
`items`가 항상 `grid`와 일관되게 기록되므로 grid를 모르는 구 코드가 읽어도 정상 렌더된다(스키마 v4 유지).

### 목적함수와 제약의 분리

cols 탐색은 **채움률(fill)을 최대화**하되 **`photoBounds` 가드레일**을 넘는 후보를 탈락시킨다.
v8.7까지의 `argmax cellW`(셀 폭 최대화)가 오너가 말한 "왁! 큰 느낌"의 직접 원인이었다 —
알고리즘이 '크게 채우기'를 최적화하고 있었다. 두 요구는 반대 방향이라 하나는 목적함수, 하나는 제약이어야 한다.
⚠️ 가드레일 상수는 눈대중 금지 — 솔버 출력으로 역산하고 `verify-collage-layout.js`가 고정한다.

| 템플릿 | 갭:여백(FHD) | 언어 |
|---|---|---|
| `mosaic` | 27px : 81px (1:3) | 매거진 리듬 — 2×2 히어로 허용, 행마다 넓은 칸 위치 회전 |
| `minimal` | 32px : 97px (1:3) | 절제 — 히어로 없음, `splitCols`가 만드는 자연스러운 크기 차만 |
| `matte` | 59px : 131px (1:2.2) | 액자 — 균일 1×1, 흰 매트 카드 + **무크롭(`object-contain`)**, 짧은 행은 가운데 정렬 |

여백은 전부 **minDim(짧은 변) 비례**라 축과 무관하게 픽셀 등방이다(v8.7까진 폭 정규화라 16:9에서 좌우 38 / 상하 32px 비대칭).
v8.7 실측 여백:갭이 1.3:1이었던 것을 3:1로 올린 것이 "왁!" 해소의 절반이고, 나머지 절반은 가로형 타이포 축소(연도 76→56px)다.

### 배경색은 세 템플릿 공통 축

`BoardData.collageBgColor` **전역 1개** — 템플릿을 바꿔도 고른 색이 따라와야 "내 보드 색"이 성립한다.
미설정이면 `TEMPLATE_DEFAULT_BG`(mosaic 크림 / minimal·matte 흰색)라 기존 사용자는 무회귀.
`COLLAGE_THEMES` 상수는 `themeFor(template, bgColor)` 함수로 승격됐다 — `dark`가 배경색 파생값이 되어
상수 테이블로 표현할 수 없기 때문. DOM·canvas가 이 함수 하나만 호출해 락스텝을 지킨다.
어두운 배경에서는 `titleInkFor()`가 글자색을 반전하고, 사진 그림자는 밝은 링으로 바뀐다(그림자는 다크에서 안 보인다).

### 편집 인터랙션

이동 = **스왑**(자리 교환, 스팬은 사진이 아니라 '자리'에 귀속), 리사이즈 = **스팬 등급 1..4 스냅**,
탭 액션에 `크게`/`작게`(모바일 주 동선). 좌표를 자유롭게 바꾸는 경로가 없으므로 그리드는 깨질 수 없다.
회전은 **자유 배치 토글**과 스티커에만 남는다 — 회전 bbox가 이웃 셀을 침범해 "빈틈 0"과 논리적으로 모순이다.

⚠️ **계약 변경**: 그리드 모드에서 사진을 추가하면 기존 사진 좌표가 **움직인다**(v8.x의 "기존 rect 불변"과 충돌).
"항상 빈틈 없이"의 필연적 귀결이며, 보존되는 것은 좌표가 아니라 **읽기 순서**다.

v9.0에서 숲(`polaroid`) 템플릿은 삭제됐다 — 회전·지터 좌표라 균일 그리드로 재해석이 불가능해
`storage.ts migrateCollage`가 `matte`로 이관하고 구 배치는 버린다(사진은 무손실, 1회 안내 배너).
`lib/colors.ts`의 `FOREST`는 산책길 지도·미니보드에서 계속 쓰인다.

### 문구 스티커 3스타일

| 스타일 | 모양 | 서체 |
|---|---|---|
| `script` | 손글씨, 색상 선택 가능 | Enjoystories 700 |
| `chip` | 흰 종이 라벨 + 그림자 | Pretendard 600 |
| `outline` | 흰 채움 + 잉크 아웃라인, 대문자 | Pretendard 800 |

글자 크기 = 항목 폭 × 보드 폭 × `STICKER_FONT_RATIO` — DOM(cqi)과 canvas가 같은 식을 써서
화면과 저장 이미지가 일치한다(WYSIWYG). 스티커는 그리드 밖 자유 배치 오버레이라 회전이 유지된다.
배경화면 내보내기는 `renderBoardLayout()`이 화면 배치를 선택한 해상도로 1:1 옮긴다(무크롭 WYSIWYG).
저장 진입은 '폰 배경화면 저장'/'PC 배경화면 저장' 2버튼 — 시트 안에서 기기를 다시 고르지 않는다.

### 높이 예산 (`--board-reserve`)

PC 무스크롤(`verify-v87r1` V87-4d)과 보드 폭 ≥1000px(V87-4e)은 서로 반대 방향이라
**눈대중 금지 — 반드시 테스트로 역산**한다. v9.0에서 배경색 팔레트 행과 보드 위 가이드 알약이
추가돼 PC 예산을 17→20rem으로 올렸고, 알약은 `lg`에서 패딩을 줄여 보드 폭 여유를 지켰다(1031px).
